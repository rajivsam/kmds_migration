# SBA Modeling Requirements

## Purpose

This project uses a notebook-first modeling workflow. The canonical modeling source is the numeric dataset exported by `notebooks/sba_featurization.ipynb`, not a second random split created within the modeling step.

The notebook is the primary implementation. The existing CLI modeling package in `models/sba_example` remains a utility layer that can be mapped onto the same logic later for automation or batch execution. The notebook is the source of truth for experimentation and reporting.

## Canonical data contract

1. Read the model-ready output from `data/featurization/model_ready_numeric_data.csv`.
2. Require the following columns:
   - `loan_status_r`
   - `dataset_partition`
   - all engineered numeric feature columns generated by the featurization notebook
3. Use `dataset_partition` as the only canonical split source.
4. Supported partitions:
   - `train`
   - `validation`
   - `test`
   - `active` (optional for later scoring)
5. Never re-split the data inside the modeling notebook.
6. The final operating cutoff is derived only from the model-ready features, calibrated validation scores, and validation labels. Raw SBA business-value fields are not required for threshold tuning.

## Featurization-to-modeling boundary

The featurization notebook is responsible for the following:

- limiting the raw feature universe to the five highest-ranked screener features:
  - `bankname`
  - `bankcity`
  - `initialinterestrate`
  - `bankstreet`
  - `terminmonths`
- applying train-only median imputation to numeric features;
- fitting categorical encoding only on the training split using `category_encoders.MEstimateEncoder`;
- exporting numeric model-ready training, validation, and test data with `dataset_partition` and `loan_status_r`.

The modeling notebook consumes this exact five-feature output directly. It does not re-encode categories, add derived geographic features, or learn a new feature set from validation/test rows.

## Target definition

Treat the problem as a binary classification task:

- `loan_status_r == 0`: good loan
- `loan_status_r == 1`: charged-off or distressed loan
- `loan_status_r == -1`: active / unlabeled score-only row

Only labeled train/validation/test rows are used for model fitting and evaluation. Active rows remain out-of-scope for the training loop and are only scored after the model and threshold are frozen.

## Modeling notebook workflow

The notebook `notebooks/sba_modeling.ipynb` must implement the following stages:

1. data loading and validation
2. feature selection from the model-ready output
3. train/validation/test partition filtering
4. model selection on the training split
5. isotonic calibration of the first-stage classifier
6. validation-only recall-first threshold diagnostics
7. validation cumulative gains and lift analysis
8. elbow-based selection of the validation review percentile and score cutoff
9. test-set evaluation with the frozen model and cutoff
10. artifact export and reporting

This notebook is the canonical implementation for model development and evaluation, and it should be structured in a way that can later be wrapped by a CLI utility in the modeling package.

## Model selection and training policy

Model development is performed on the training split only.

Recommended model candidates:

- `GradientBoostingClassifier`
- `RandomForestClassifier`

The first-stage classifier must be calibrated with `IsotonicRegression` trained on training probabilities or, alternatively, a `CalibratedClassifierCV` using isotonic calibration fitted on train-only data. The calibration step is required to produce a better-ranked probability score for screening and review prioritization. The training loop must not inspect test labels at any point.

Missing numeric values in the model-ready feature matrix must be handled with a training-only imputer (for example, median imputation on the train split) so the modeling pipeline remains leakage-safe and robust to sparse feature rows.

## Validation-based threshold tuning

Threshold tuning occurs only on the validation split and is implemented in two stages.

Stage A: recall-first screening threshold

- score all validation rows with the calibrated first-stage classifier;
- rank rows by descending calibrated probability;
- find the threshold that maximizes validation recall;
- if multiple score thresholds achieve the same maximum recall, choose the one with higher precision;
- retain this as a first-stage model diagnostic and do not use test labels to tune it.

Stage B: elbow-based operating review cutoff

- score and rank every validation row by descending calibrated default probability;
- group the ranked rows into ordered deciles or percentiles;
- at each cumulative cutoff `k%`, calculate:
  - `cumulative_gains = defaults captured in top k% / all validation defaults`;
  - `lift = cumulative_gains / k%`;
  - the number and percentage of rows reviewed;
  - the calibrated probability at the cutoff boundary;
- normalize the cumulative population and gains axes to `[0, 1]`;
- select the elbow as the point with the greatest positive vertical distance from the random-selection baseline, where cumulative gains equals cumulative population;
- use the lower review percentile when multiple cutoffs have the same distance;
- if the curve does not rise above the random-selection baseline, use 100% as the conservative elbow cutoff;
- freeze both the selected `k%` and the calibrated probability at that boundary before evaluating test data;
- for batch scoring, preserve the selected top-`k%` cohort;
- for individual loan scoring, apply the frozen calibrated probability threshold with `score >= threshold`;
- record score ties at the selected boundary. If a threshold has tied scores extending below the selected percentile, applying the probability threshold necessarily reviews more than `k%` and the larger observed review rate must be reported rather than treating `k%` as the realized rate.

The second-stage cutoff is selected from cumulative validation gains and lift. It is not selected from precision, F1, business-value deciles, or test performance.

## Test evaluation

The frozen model and elbow-derived threshold are applied once to the test partition. Report the following metrics:

- precision
- recall
- F1
- balanced accuracy
- PR-AUC / average precision
- review rate / population reviewed
- cumulative gains and lift at the selected review cutoff
- the selected review percentile and frozen score threshold

Test results are for final evaluation only. They are not used to change the model or threshold after the fact.

## CLI mapping and compatibility

The notebook is the primary workflow, but the repository’s modeling package should remain compatible with the same conceptual pipeline:

- load the featurized model-ready dataset;
- use the same train/validation/test partitions;
- train the same candidate models;
- calibrate the first-stage model with isotonic regression;
- build the same validation cumulative gains/lift table;
- select the same elbow-based review percentile and score cutoff on validation;
- evaluate the same metrics on test;
- serialize the trained model and threshold metadata.

This allows a future CLI or batch runner to call the same logic without changing the notebook-driven design.

## Required outputs

The notebook should produce a reproducible set of artifacts, including:

- the champion model object;
- the first-stage recall-maximizing threshold;
- the selected validation elbow percentile;
- the final operating probability threshold at that elbow;
- the validation cumulative gains/lift table;
- final test-metrics summary;
- feature list used for modeling;
- selected split labels and partition metadata;
- any serialized artifacts that a CLI utility may later consume.

## Acceptance criteria

The modeling workflow is considered complete when:

- the notebook loads the canonical model-ready featurization output;
- the train/validation/test partitions are used from `dataset_partition` without a second random split;
- candidate models are trained on train data only;
- the validation split is used for calibrated first-stage selection and elbow-based gains/lift cutoff tuning;
- the Stage 2 cutoff is based only on validation cumulative gains and lift, using the elbow approach above;
- the test split is evaluated once with the frozen calibrated model and frozen elbow cutoff;
- the notebook reports the final model performance on the holdout test set;
- missing values are handled with a train-only imputation strategy;
- the notebook is structured so the same logic can be wrapped by the CLI modeling package later.
